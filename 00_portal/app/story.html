The new brief
How do we get from prototype to reality?
The browser chrome, native device UI, and overlaid site interactions — not just the design in isolation
The solution
Three layers. One shared working environment.
Each layer is independent. Swap the shell, keep the prototype. Update a shared component once, it updates everywhere.

And thinking about scale — if one designer hit all these friction points, the entire Wilson DS team would multiply every one of them. The shells became a shared working environment to unify how the whole team builds and presents, not just a wrapper for one prototype.
Layer 3
Design Prototype
The design work — destinations, events, homepage. Authored per component, swappable.
Layer 2
Shared Components
Nav, footer, booking bar — written once, mounted into any prototype via URL params.
Layer 1
Device Shell
iOS Safari, Android Chrome, Desktop — realistic chrome, shared across the whole team.
Step one
First, a simple index

It solved the immediate problem — but surfaced the next one. The index was a list, not a workflow.
